# 邮箱验证码助手平台化实施进度

更新时间：2026-08-20  
依据：`邮箱验证码助手_平台化建设方案.docx`

## 总体边界

- 默认 EXE 入口只使用平台客户端，不读取邮箱原始账号密码，也不直连邮件代理或 Sub2 管理端。
- 邮箱、卡、上传资源均绑定 `tenant_id + user_id + device_id + task_id + trace_id`。
- Sub2 Token、代理、分组、并发和模型策略只能由服务端 Worker 读取，客户端请求模型不包含这些字段。
- access token 只保存在进程或页面内存；Windows refresh token 使用用户级 DPAPI 和设备绑定 entropy。
- 验证码、PAN/CVV 不进入普通日志或审计详情；上传网络歧义进入 `unknown`，不自动盲目重试。

## 下一轮必须确认的输入

1. Sub2 是标准 HTTP API 还是网页后台；提供脱敏请求/响应和鉴权说明。
2. 邮箱接口的 URL、鉴权方式、请求/响应样例、限流和验证码邮件规则。
3. 卡字段是否包含 PAN/CVV，以及 PCI 合规边界；当前 API 默认永不返回 CVV。
4. 目标 Keycloak 中 `urn:email-platform:acr:mfa` 应映射 OTP 还是 WebAuthn LoA。
5. 生产域名、证书来源、Keycloak/Vault 地址、预计用户数和并发任务数。
